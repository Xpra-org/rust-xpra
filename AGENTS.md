# Repository guidance

## Version updates

For every version bump, check all files below individually. Do not rely only on
searching for the version currently in `Cargo.toml`: another file may already be
stale. Before the 0.5.0 update, `packaging/rust-xpra.1` still advertised 0.3.0 and
`exe.manifest` still used 0.1.0.0. The Debian build script's tarball selector also
remained at `0.3.*` after the 0.4.0 and 0.5.0 bumps.

| File | What to update |
| --- | --- |
| `Cargo.toml` | `[package].version` to `X.Y.Z`. |
| `exe.manifest` | `assemblyIdentity` version to `X.Y.Z.0`. |
| `packaging/rust-xpra.1` | `.TH` application version and date. |
| `packaging/rpm/rust-xpra.spec` | `Version:`, versioned release URL examples in comments, and the current `%changelog` entry. |
| `packaging/debian/rust-xpra/changelog` | Current package version `X.Y.Z-1` and its entry date. |
| `packaging/debian/build.sh` | `RUST_XPRA_TAR` source glob to `rust-xpra-X.Y.*.tar.gz`, matching Cargo's major/minor version. |
| `CHANGELOG.md` | Heading for the new version; use `Unreleased` until release notes are ready. |

Preserve entries for released versions. Check Git tags before deciding whether to
add a new changelog entry or relabel an unreleased one.

`src/lib.rs` derives `CLIENT_VERSION` from `CARGO_PKG_VERSION`; the command-line
version, hello packet, and Windows version resources generated by `winresource`
follow Cargo automatically. The separate `exe.manifest` field still needs updating.

`Cargo.lock` is ignored. Let Cargo refresh its local `xpra` package version during
verification; do not add the lockfile just for a version bump.

The RPM spec also pins the source archive SHA-256 in `%prep`. Update it from the
actual release tarball when available. If the new tag/archive does not exist yet,
report that the checksum remains pending; do not invent a checksum or remove the
verification.

Historical references, dependency versions, and dated dependency-graph snapshots
are not current application version fields. Regenerate `docs/dependency-graph.html`
with `python3 docs/dependency-graph.py` when updating its dependency snapshot;
do not replace version strings inside the generated file by hand.

Before finishing:

- Search for other application version literals, including values older than the
  version being replaced, and review whether they describe current or historical
  behavior.
- Run `cargo run --offline -- --version` and confirm it reports the new version.
- Run `dpkg-parsechangelog -lpackaging/debian/rust-xpra/changelog -S Version`
  when available and confirm the new package version.
- Run `cargo test --offline --test packaging_version` to check the Debian source
  tarball selector against Cargo's major/minor version, and run
  `bash -n packaging/debian/build.sh` to check the script's syntax.
- Review the diff against the checklist above and run `git diff --check`.
